# 开发顺序、联调与验收

## 1. 队友第一小时做什么
1. 克隆仓库，先读 PROJECT_GUIDE 和 FRONTEND_MODULES，不要从MainActivity全部源码开始猜。
2. 运行Web参考或打开线上手机预览，按下方路线逐页看。
3. 打开Android的workspace-demo.json；服务端先原样返回该JSON。
4. 确认Bearer认证方案、金额单位、错误结构；给出测试服务地址。
5. Android“连接设置”请求GET /api/workspace；先验证内容一致，再改成数据库查询。

## 2. 阶段交付
| 阶段 | 后端 | Android | 通过条件 |
|---|---|---|---|
| S0 基线 | mock GET返回完整快照 | 能加载并浏览 | 3标的、180报价、7交易、3资金、3笔记一致 |
| S1 认证/存储 | 登录、账户隔离、数据库 | 登录、token处理、多账户 | A用户不能看B账户；重启服务记录仍存在 |
| S2 账本闭环 | CRUD、事务、事件重放 | 资金/交易/笔记编辑器 | 保存更新估值；非法历史修改被拒绝 |
| S3 分析 | 日期范围、缺样本、相关性 | 筛选、图表、单位、来源 | 手算样例一致，筛选前后口径明确 |
| S4 模型 | 真实任务与评估 | 配置、进度、错误、结果 | 结果可追溯到数据和模型版本 |

## 3. 页面演示路线（给不懂前端的队友）
首页看数据范围 → 分析看曲线/表/口径 → 市场选择标的看单价 → 组合核对资产/净投入/盈亏 → 规则对照看同资金差异 → 账本核对原始记录 → 复盘看理由/预期/结果 → 模型看划分和混淆矩阵 → AI看上下文与引用 → 来源看数据口径。
每个模块的具体含义见FRONTEND_MODULES，不把图表的颜色当作算法定义。

## 4. 必测操作
- 空状态：空账户、无价格、仅1条价格、没有交易、没有笔记。
- 账本：先入金再买入；份额为负/小数拒绝；手续费非负；卖出超过持仓拒绝；历史删除导致后续透支拒绝。
- 分析：日期无数据、起止倒置、日期交集少于3、零方差序列；缺失显示不可计算而非0。
- 数据：重复日期、无效日期、负价格、两位以上小数、代码冲突、不同复权口径。
- 网络：超时、401、403、500、空响应、缺字段；保留用户输入并提供重试。
- 模型：排队、运行、失败、取消、无特征；结果不一致时不展示成功。
- AI：空问题、过长问题、停止、断流、限流；不要用旧回答冒充新问题的结果。
- Android：窄屏、系统字体放大、输入法遮挡、返回键、旋转、切后台再回、长列表滚动。

## 5. 文档与代码的明确缺口
- 当前Android仍是顶部滚动导航；手机预览的底部导航尚未落地原生代码。
- Android工程缺Gradle Wrapper；必须补齐并在Android Studio构建，尚无APK验收证据。
- Android很多页面只读；不能用Web CRUD通过代替原生功能完成。
- Web模拟交易删除与早期服务端笔记处理策略不一致，冻结后端前必须统一。
- 线上 `/mobile` 当前尚未同步GitHub基线。本轮提交仅补充文档，不声称代码同步。
- 没有真实模型训练、DeepSeek调用、正式登录、可用生产后端。

## 6. 分支与沟通
建议android/*、backend/*、analysis/*分支；PR附“改了什么、接口变化、验证证据、未完成项”。先同步契约，再修改消费方。不要直接强推覆盖队友提交；金额/日期/口径变更必须写迁移说明。
定位问题时提供：页面、操作步骤、输入、期待、实际、HTTP状态/requestId、提交SHA。不要仅说“这块不对”。
